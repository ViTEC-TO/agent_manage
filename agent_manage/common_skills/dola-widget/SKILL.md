# Dola 小组件

让用户在对话中直接操作一个轻量界面。生成 HTML 文件，再用 `dola-widget` 消息标记交付；不要把完整 HTML 粘贴进回复，也不要把普通 HTML 链接默认当作小组件。

## 何时主动启用

满足下列情况之一，且交互能帮助用户完成当前问题时，主动采用小组件，无需再次询问是否使用：

- 输入或调整参数后查看结果：预算、成本、时间估算、单位换算、情景模拟。
- 切换、筛选或比较信息：图表、方案比较、时间线、步骤与路径探索。
- 需要轻量操作：颜色或布局预览、选择器、小游戏、可交互的原理演示。
- 用户明确要求在 chat 中展示可操作的页面、小工具或小组件。

一句话、普通表格或静态图片就能清楚回答时，优先直接回答。不要为了展示界面而扩大任务。用户要完整网站、正式报表或可下载文档时，保留这些交付目标；小组件只能作为有实际帮助的补充。

第一版以组件内交互为主。不要假设小组件能调用 Agent、修改平台数据、提交订单或直接读取平台 API；这些操作需要宿主已实现的桥接与授权。

## 生成与交付

1. 明确本组件帮助用户做哪件事，选择足够的输入、结果与交互。
2. 从当前实例的运行规则读取真实公共文件根目录和交付 base URL。不要从平台域名猜实例域名，不要写死 CN/global 域名。若缺失或无法确认，说明缺少的交付配置，不输出虚构地址。
3. 使用公开文件交付能力；若已安装 `nginx-delivery`，遵循它的部署流程。创建公共目录下的 `widget/` 子目录，URL 路径固定为 `/widget/<id>-v<version>.html`。不要修改无关服务配置或部署文件。
4. 检查公开范围。自动选择小组件不等于获准公开私密信息；不要把私人对话、凭据、个人信息或私密业务数据放入公开 HTML。可用模拟或去标识数据完成任务时优先使用，并标明数据性质；必须保留私密数据时使用宿主已有的私有交付机制，若不存在则说明限制，不假装公开地址是私密地址。
5. 完成文件后验证真实交付 URL，再输出小组件标记和一句用途说明。写入成功只代表文件存在，不代表前端已显示。

## HTML 要求

- 优先单文件 HTML，CSS 与 JavaScript 内联，使用原生浏览器能力；必要资源才另放 `/widget/`，使用相对路径。避免依赖 npm 构建或不必要的第三方 CDN。
- 宽度随容器变化，使用 `width: 100%`、`box-sizing: border-box` 和 viewport meta；在约 320px 宽度也能使用，不固定桌面宽度或造成横向溢出。
- 默认建议高度 360px，按内容选择 180–720px 的整数高度；高度是宿主展示建议，不是固定窗口保证。较长内容提供组件内滚动或缩减首屏，不假设宿主有全屏功能。
- 语言跟随当前用户，标明单位、输入范围、计算口径及模拟数据。
- 默认采用与 Dola chat 融合的深色主题，不因浏览器或系统偏好浅色而自动变成大面积白底。只有用户明确要求浅色，或宿主明确传入浅色主题时，才切换浅色。
- 参考配色：页面背景 `#181818`；卡片/输入背景 `#222222`；悬停背景 `#2A2A2A`；主文字 `#E1E1E1`；次级文字 `#A0A0A0`；边框 `rgba(255,255,255,0.10)`；强调色 `#DDC99C`。可以按内容调整，但保持整体深色与文字对比度，不把所有文字都做成低对比灰色。
- 在 `html`、`body` 和最外层容器明确设置深色背景、文字颜色，设置 `color-scheme: dark` 让原生输入控件协调；图表绘图区、表格、提示框和第三方组件也要适配。图片本身需要白底时可以局部保留，不要因此把整张组件变成白底。
- 核心交互在组件内完成；按钮、输入框有明确标签，支持键盘操作。不要添加没有实现行为的按钮。
- 不读取父页面 DOM、Cookie、localStorage 或认证信息；不把 Token 放进 HTML、资源 URL 或输出。不要自行扩大 iframe 权限，不依赖 `allow-same-origin`。
- 默认不联网、不采集用户输入、不自动提交表单、不自动播放媒体。需要外部数据时说明来源，并仅使用宿主实际允许的访问能力；不要绕过隔离限制。
- 所有结果必须来自实际数据或实现的计算。参数变化要更新结果；不要用装饰性的随机变化伪装真实计算。

## 小组件交付协议 v1

使用下列专用代码块，内容必须为合法 JSON，无注释、尾逗号或额外的 HTML。不要使用 `MEDIA:` 交付 HTML，以免进入图片附件链路。

```dola-widget
{
  "id": "budget-calculator",
  "version": 1,
  "title": "预算计算器",
  "src": "/widget/budget-calculator-v1.html",
  "height": 360
}
```

- `id`：当前对话内稳定的组件标识，使用小写英文字母、数字和连字符，如 `budget-calculator`。
- `version`：从 1 开始的正整数。同一组件修改后递增；新组件使用新 ID。
- `title`：简短、能说明用途的展示名称，语言跟随用户。
- `src`：以 `/widget/` 开头的根相对路径，指向该实例已经交付的 HTML 文件，不包含协议、域名、Token、查询参数、`..` 或本地路径。
- `height`：180–720 的整数，单位为 CSS 像素。宽度由 chat 容器控制，不输出 `width`。

`src` 应由宿主基于当前实例的真实交付 base URL 解析，而不是基于 Dola 网站域名或浏览器当前地址。Skill 本身不实现这个宿主行为。

在代码块外再提供经过验证的完整 HTTPS URL 作为“单独打开”链接；只有实际配置为 HTTP 时才使用真实 HTTP URL。它必须对应 `src` 的同一个文件。这样前端未接入小组件解析时，用户仍能打开页面。链接必须可访问，不含认证信息。

## 更新已有组件

先找到当前对话已有的组件 ID 和版本。修改同一个组件时保留 ID，版本加 1，交付新版本文件并输出完整的新标记。不要原地覆盖旧版本 HTML，避免旧消息与缓存显示不同内容。宿主是否在同一卡片更新由前端实现，不能仅凭输出标记宣称更新已经显示。

若无法确定原 ID 或版本，不猜测版本号；说明缺少原标记。仅当用户确实需要独立的新组件时才创建新 ID。

## 完成前检查

- 验证 JSON 字段、ID、版本、路径与实际文件一致；检查所有引用资源。
- 用浏览器验证初始展示、至少一个核心交互、输入边界和手机宽度。若无浏览器能力，如实说明交互未实测，不宣称全部可用。
- 对最终完整 URL 执行有界请求，例如 `curl -4 --max-time 5`，确认成功响应和 HTML 内容；检查是否有阻止宿主嵌入的响应头。不能靠首页可访问推断组件文件可访问。
- 交付失败时修正可定位的问题后再验证；仍失败就说明原因，不输出成功的小组件标记。可以保留文件供后续修复，并用文字提供已确认的结果。
- 回复保持简短：用途说明、`dola-widget` 标记、单独打开链接。不要重复讲解界面已有的全部内容。
